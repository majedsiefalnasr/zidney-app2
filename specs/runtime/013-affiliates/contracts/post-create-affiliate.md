# Contract: POST /v1/mmc/affiliates

**Purpose**: Create a new affiliate promo code  
**Authentication**: MMC service token + admin RBAC  
**Authorization**: `affiliates:create` permission  
**Rate Limit**: Standard admin endpoint limit (~100 req/min per admin)

---

## Request

### Headers

```
Authorization: Bearer <mmc-service-token>
Content-Type: application/json
X-Correlation-ID: <uuid>  (generated by client or left for API to generate)
```

### Body

```json
{
  "promo_code": "SPRING25",
  "discount_percentage": 10.5,
  "commission_percentage": 2.75,
  "usage_limit_total": 1000,
  "usage_limit_per_client": 5,
  "start_date": "2026-03-01T00:00:00Z",
  "end_date": "2026-05-31T23:59:59Z",
  "allow_with_other_discounts": false,
  "description": "Spring promotional code for institutional partners"
}
```

### Field Specifications

| Field                        | Type               | Required            | Constraints                                | Notes                                  |
| ---------------------------- | ------------------ | ------------------- | ------------------------------------------ | -------------------------------------- |
| `promo_code`                 | string             | YES                 | Uppercase alphanumeric, 3-50 chars, UNIQUE | Must match `^[A-Z0-9]{3,50}$`          |
| `discount_percentage`        | number             | YES                 | 0.00 - 100.00, 2 decimals                  | Applied to base license amount         |
| `commission_percentage`      | number             | YES                 | 0.00 - 100.00, 2 decimals                  | Commission to affiliate from discount  |
| `usage_limit_total`          | integer or null    | YES                 | >= 0                                       | `null` = unlimited global uses         |
| `usage_limit_per_client`     | integer or null    | YES                 | >= 0                                       | `null` = unlimited per-client uses     |
| `start_date`                 | ISO 8601 timestamp | YES                 | start < end                                | Promo code active from this time       |
| `end_date`                   | ISO 8601 timestamp | YES                 | end > start                                | Promo code inactive after this time    |
| `allow_with_other_discounts` | boolean            | NO (default: false) | true/false                                 | Discount stacking permission           |
| `description`                | string             | NO                  | max 1000 chars                             | Admin notes (not visible to customers) |

### Validation Rules

**Request-Level** (Application):

- `promo_code`: Uppercase check, length 3-50, alphanumeric only
- Percentages: Must be valid numbers 0-100 with max 2 decimals
- Date range: start_date < end_date (non-increasing order error)
- Limits: Must be null or non-negative integers

**Database-Level** (Constraints):

- UNIQUE on promo_code (prevents duplicates)
- CHECK constraints on percentages (0-100)
- CHECK on start_date < end_date

    "allow_with_other_discounts": false,
    "description": "Spring promotional code for institutional partners",
    "created_at": "2026-02-25T14:30:00.123Z",
    "updated_at": "2026-02-25T14:30:00.123Z"

### Response Field Notes

- `id`: UUID of created affiliate record
- `discount_percentage`, `commission_percentage`: Returned as strings (NUMERIC type from DB)
- `usage_count`: Always 0 for new record
- `status`: Always "ACTIVE" for new affiliates
- `created_at`, `updated_at`: Server timestamps (UTC)

## Transaction Flow

```
1. Parse and validate request body (Zod schema)
2. Check admin authentication (MMC token)
3. Check RBAC authorization (affiliates:create)
4. BEGIN PostgreSQL transaction
5. Generate UUID for affiliate record
6. INSERT into affiliates table
7. INSERT into affiliate_admin_audit (action='CREATE')
8. COMMIT transaction
9. Return 201 with created affiliate data
```

## Implementation Notes

### Idempotency

- **Not Idempotent**: Each POST creates a new record. Duplicate requests create duplicate affiliates.
- **Mitigation**: Client should maintain idempotency key or retry logic should verify existing record by promo_code

### Race Conditions

- UNIQUE constraint prevents concurrent duplicate inserts (database rejects, returns error)

### Performance

- Expected response time: < 50ms (single INSERT + audit log)
- No external dependencies
